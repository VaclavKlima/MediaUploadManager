# v0.1.0-beta.2 — NAS media group compatibility

## Operator contract

This procedure upgrades `v0.1.0-beta.1` to `v0.1.0-beta.2`. Beta.1 kept the application process at the configured primary `APP_UID:APP_GID`, but it did not add the NAS media group as a supplemental group. With `fs.protected_hardlinks=1`, imports from legacy files owned by another group could therefore fail at hard-link creation even when normal file reads worked.

Beta.2 uses Compose [`group_add`](https://docs.docker.com/reference/compose-file/services/#group_add) to add `MEDIA_GID` to only the five media-accessing services and reports an actionable, path-free failure when the kernel denies a hard link. It does not add a database migration. It does not change the hard-link/unlink import design, primary process identity, NAS ownership, volumes, Cloudflare configuration, or `fs.protected_hardlinks`.

An AI operator must execute this procedure exactly, stop at every stated stop condition, and keep all paths, command output, credentials, and environment contents in the trusted terminal. Do not paste them into chat, tickets, or logs shared with third parties.

## Required environment change

In the existing untracked `deploy/production/.env.production`, retain these existing values and add the third value exactly:

```dotenv
APP_UID=1000
APP_GID=100
MEDIA_GID=50
```

Set both image variables to the matching immutable beta.2 tags from this repository's GHCR namespace:

```dotenv
APP_IMAGE=ghcr.io/OWNER/REPOSITORY-app:v0.1.0-beta.2
NGINX_IMAGE=ghcr.io/OWNER/REPOSITORY-nginx:v0.1.0-beta.2
```

Do not change any other environment value as part of this release.

## Preflight

Work from the existing production checkout. Define command aliases without printing or rendering the environment:

```bash
export COMPOSE_FILE=deploy/production/compose.yml
export COMPOSE_ENV=deploy/production/.env.production
test -f "$COMPOSE_ENV"
set -a
. "$COMPOSE_ENV"
set +a
```

Confirm every configured media root is an active mount. These commands must produce no output on success:

```bash
findmnt --mountpoint "$MEDIA_DISK_NAS_A_PATH" >/dev/null
findmnt --mountpoint "$MEDIA_DISK_NAS_B_PATH" >/dev/null
findmnt --mountpoint "$MEDIA_DISK_NAS_C_PATH" >/dev/null
```

Stop if any mount is missing or resolves somewhere other than its configured root.

Have the human set `REPRESENTATIVE_SOURCE` to one legacy movie on each configured root, one at a time. Inspect numeric ownership and modes locally; do not post the path or output anywhere:

```bash
stat -c '%u:%g %a %n' -- "$REPRESENTATIVE_SOURCE"
namei -l -- "$REPRESENTATIVE_SOURCE"
```

For every representative file, require numeric GID `50` and group-write permission:

```bash
test "$(stat -c '%g' -- "$REPRESENTATIVE_SOURCE")" = 50
find "$REPRESENTATIVE_SOURCE" -maxdepth 0 -type f -gid 50 -perm -g=w -print -quit | grep --quiet .
```

Review every parent directory shown by `namei -l`. Each directory from the mounted root through the source parent and intended canonical destination parent must be traversable by group `50`; directories where a canonical destination may be created must also be group-writable. Stop if ownership is inconsistent across representative legacy files, if any required parent lacks group traversal, or if any required destination parent lacks group write.

Confirm protected hard links remain enabled:

```bash
test "$(sysctl -n fs.protected_hardlinks)" = 1
```

Confirm the current checkout has no tracked changes before fetching. The untracked production environment is intentionally ignored:

```bash
test -z "$(git status --porcelain --untracked-files=no)"
```

Stop for a dirty tracked checkout. Do not stash, discard, or overwrite production changes automatically.

## Fetch and select the immutable release

Fetch and check out only the annotated beta.2 tag:

```bash
git fetch origin tag v0.1.0-beta.2
git checkout --detach v0.1.0-beta.2
test "$(git describe --tags --exact-match)" = v0.1.0-beta.2
test -z "$(git status --porcelain --untracked-files=no)"
```

Open the untracked environment in a trusted terminal editor. Retain `APP_UID=1000` and `APP_GID=100`, add `MEDIA_GID=50`, and change both image tags to `v0.1.0-beta.2`:

```bash
"${EDITOR:?Set EDITOR to a trusted terminal editor}" "$COMPOSE_ENV"
set -a
. "$COMPOSE_ENV"
set +a
test "$APP_UID" = 1000
test "$APP_GID" = 100
test "$MEDIA_GID" = 50
test "${APP_IMAGE##*:}" = v0.1.0-beta.2
test "${NGINX_IMAGE##*:}" = v0.1.0-beta.2
```

Confirm both immutable GHCR tags exist and are available to the authenticated production host without printing manifests:

```bash
docker manifest inspect "$APP_IMAGE" >/dev/null
docker manifest inspect "$NGINX_IMAGE" >/dev/null
```

Validate Compose without rendering interpolated secrets:

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" config --quiet
```

Stop for a tag mismatch, missing GHCR image, failed authentication, or failed Compose validation. Never run plain `docker compose config`.

## Deploy

Enter maintenance mode, pull the exact images, run the one-shot migration/media preflight, recreate the listed services, wait for health, restart Pulse, and leave maintenance mode:

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec app php artisan down
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" pull app migrate nginx
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm migrate
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" up --detach --force-recreate app worker scheduler pulse tusd nginx cloudflared
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" up --detach --wait --wait-timeout 180
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec app php artisan pulse:restart
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec app php artisan up
```

If any command fails after maintenance mode begins, stop, preserve all containers and volumes, collect only redacted diagnostics, and do not retry an import.

## Post-deployment verification

Prove GID `50` is supplemental in exactly the five media services. These assertions produce only the matching numeric GID:

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm --no-deps --entrypoint id migrate -G | tr ' ' '\n' | grep --fixed-strings --line-regexp 50
for service in app worker scheduler tusd; do
  docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec -T "$service" id -G | tr ' ' '\n' | grep --fixed-strings --line-regexp 50
done
```

Confirm the primary identity was not changed:

```bash
test "$(docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm --no-deps --entrypoint id migrate -g)" = 100
for service in app worker scheduler tusd; do
  test "$(docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec -T "$service" id -u)" = 1000
  test "$(docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec -T "$service" id -g)" = 100
done
```

Confirm media disk checks, scheduler visibility, Pulse restart, protected hard links, and container health:

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec app php artisan media:disks:check
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec app php artisan schedule:list
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec app php artisan pulse:restart
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" ps
for service in mysql app worker scheduler pulse tusd nginx cloudflared; do
  docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" ps --status running --services | grep --fixed-strings --line-regexp "$service"
done
test "$(sysctl -n fs.protected_hardlinks)" = 1
```

Stop if a group assertion, primary identity assertion, disk check, scheduler check, Pulse command, protected-hard-link assertion, or container health check fails.

## Retry a failed import

Retry only after every post-deployment check passes. Have the human set `FAILED_SOURCE` and record its device and inode in trusted shell variables before using the administrator interface:

```bash
read -r FAILED_SOURCE_DEVICE FAILED_SOURCE_INODE < <(stat -c '%d %i' -- "$FAILED_SOURCE")
test -n "$FAILED_SOURCE_DEVICE"
test -n "$FAILED_SOURCE_INODE"
```

Retry only through the existing administrator import action. Do not invoke a job manually. On failure, stop and leave the claim and source untouched.

After the administrator action reports success, have the human set `CANONICAL_DESTINATION` from the application result and verify that the source disappeared only after success and the destination retained the exact recorded device/inode:

```bash
test ! -e "$FAILED_SOURCE"
read -r DESTINATION_DEVICE DESTINATION_INODE < <(stat -c '%d %i' -- "$CANONICAL_DESTINATION")
test "$DESTINATION_DEVICE" = "$FAILED_SOURCE_DEVICE"
test "$DESTINATION_INODE" = "$FAILED_SOURCE_INODE"
```

Keep these values and all paths out of chat and tickets.

## Prohibited actions

Do not:

- recursively `chown` or `chmod` any NAS tree;
- disable or lower `fs.protected_hardlinks`;
- manually move, rename, link, or copy a failed source file;
- delete or alter failed import claims;
- run Compose commands that render secrets, including plain `docker compose config`;
- retag, overwrite, or mutate beta.1 images or tags;
- add a rename/copy fallback or delete a source before the exclusive hard link succeeds;
- run `docker compose down --volumes` or delete any production volume.
